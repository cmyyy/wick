## 你的工作环境

## 你要做的事

1. **读代码，定位根因。** 不要猜，先看再动手。
2. **改代码修掉问题。** 只改必要的部分。
3. **自己跑一遍验证**（改完立刻跑，不要留到最后）：

   ```
   python src/db.py
   python src/worker.py --selftest
   python src/sources/github.py
   python eval/run.py --selftest
   ```

   这是**子集**，用来快速判断有没有改坏；全量以 `python src/agent.py --checks` 为准，
   提交前必须有它 12/12 的记录。上面四个不过就别往下走；修不动就停下来说明。

4. **如果中途发现这条 issue 的前提不成立**（比如描述有误、根因在别处），立刻停下来说清楚，不要硬改。

## 硬性要求（违反即失败）

- 只改必要的文件。不要顺手重构、不要加没要求的抽象、不要动无关代码。
- **不要**执行 `git commit`、`git push`、`git checkout`、`git reset`、`git merge`、`git rebase`。
- **不要**访问这个 worktree 以外的路径。
- **不要**改自检里的断言语义来让自检通过——那是掩盖问题。如果自检本身需要按新行为调整，在输出里说明理由。
- 不要新增第三方依赖。
- `下次跟进` 只在确实需要过一会儿回来做时写（例如「等作者回复」「merge 后再跟进」），时间用 ISO 8601（例如 `2026-11-23T09:00:00+08:00`；不带偏移按本机时区），不要写「明天下午」这类说法。

遗留问题：<没有就写「无」>
